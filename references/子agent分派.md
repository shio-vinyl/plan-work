# 子 agent 分派

研究和数据分析阶段，多用子 agent 并行；写作和定口径留在主会话。派出去的都是前提工作，按 `工作模式.md` 的前提工作做：已定口径冻结，不下方案结论。同样的规矩也用于交给另一个协作 agent 的活。

## 什么适合派

适合派的：范围清楚、结果能核对的活。

- 通读大文件，按提纲抽取：纲要、专项规划、几十页的汇报 PDF，一份文件派一个。上位规划和政策的“依据要点”也这样抽。
- 依据兜底：脚本扫完后，派 agent 独立再找一遍上位依据，一路通读材料找漏抓的提法，一路到官网查应列未列和现行状态。
- 按清单检索公开数据：按主题分组（统计、住房市场、物业），一组派一个。
- 外地案例、政策研究：按城市分（北京、广州、深圳）。
- 互不依赖的分项计算：各算各的，合表由主会话做。
- 数据对账和测算复核：口径定了以后，派出去按已定口径核账、对项目、算情景。

同时满足三个条件才派：几块之间不互相依赖；产出能用统一表头合并；主会话只要结论，不需要看过程。

不派的：

- 定口径、改结构、写正文和汇报页。这些要和用户来回讨论，而且全文风格要一致。
- 几次工具调用就能办完的小查询。派一个子 agent 的 token 和时间开销，远大于主会话自己查。

**子 agent 和子会话的区别：** 子 agent 的结果本轮就收回来用；子会话是用户要单独讨论、推进的一块工作（比如专题写作），brief 里写明“先讨论，再动手”。

## 派之前

0. **表格先提好。** 材料里的表格由主会话直接跑 `extract_tables.py` 提进项目的 `数据表/`，几秒钟的事，不必派。子 agent 通读时引用这些数据表的文件名，不再自己抄表。
1. **先把工具试通。** 网络通不通、接口能不能用、脚本跑不跑得起来，主会话先试，再把能用的命令写进 brief。不要让每个子 agent 各自摸索。
2. **给已知线索。** 比如“统计公报在这几个链接”“底稿里这几个数要核”。
3. **一次并行 3—5 个**，按来源或主题切，不要切得太碎。

## brief 通用部分

每份 brief 都有：

- **目标：** 一句话，写明是什么项目、为什么要这些数。
- **背景：** 一段，写已知口径和关键事实（不写我们的结论）。
- **工具：** 能用的命令和脚本完整路径；哪些工具不灵（比如境外搜索）。
- **清单：** 负责的数据项或文件，底稿里要核的数原样列出。
- **规则：**
  - 数字照原文抄；自己算的标“推算”。
  - 每条要有链接或页码；没找到的写“未找到”，并列出试过的关键词。
  - 查政策、公文与公告时，按 `政策与公文检索.md` 执行：优先用 `python3 -I scripts/govdoc.py`（`central`/`std`/`search`/`list`/`fetch`/`extract`），**不裸 `curl` 爬通用搜索引擎、不暴力扫站点 ID、不用 `WebFetch` 逐字核原文或下 PDF**；遇 `403`/`412`/SPA 空壳立刻降级或上报，不伪造绕过。
  - 不往项目文件夹写文件；下载放临时目录。
  - 遇到权限拦截就停下报告，不绕过。
  - 不定口径，不改结构。
- **输出：** 统一表头的 Markdown 表，加一段“和底稿的冲突”；限定字数。

## brief 模板

### 通读抽取

```
读 <文件路径>（<文件说明>）。按下面的提纲抽取，原文怎么写就怎么抄，每条注页码：
1. 指标和数字（名称、数值、时点、口径）
2. 已定的结论和任务（原文）
3. 项目清单（名称、位置、规模、时序）
4. 和 <其他文件> 不一致的地方
5. 引用的上位规划、政策和标准（名称、文号、状态写法）
输出：| 类别 | 内容 | 页码 |，不超过 N 字。
```

### 上位文件要点抽取

```
读 <上位文件路径>（<名称、文号>）。本项目是 <项目一句话>，关注 <合同条目或专题清单>。
摘出和本项目相关的原文，照抄不改写，每条注条款或页码：
| 条款或页码 | 原文 | 类型（定位/目标/指标/任务/空间安排/政策要求） | 对应条目 |
没有相关内容的条目写“无”。不超过 N 字。
```

### 公开数据检索

```
你负责 <主题> 的数据。来源优先级：政府官网 > 统计公报、年鉴、普查公报 > 部门公告附件 > 媒体。
已知线索：<链接>。要找：<数据项清单，每项写需要的年份和口径；底稿要核的数原样列出>。
输出：| 数据项 | 时点 | 数值 | 口径 | 来源标题 | URL |；再附“和底稿的冲突”。
```

### 依据兜底：材料通读

```
读 <文件路径>（<文件说明>），全文逐段读，PPT 含隐藏页、备注和版面外对象。
本项目是 <项目一句话>。找出所有指向上位要求的地方：
- 有书名号或没书名号的规划、政策、法规、标准、会议文件；
- 会议和讲话精神（如某次会议、全会、重要论述）；
- 笼统提法（“按照国家、省、市有关要求”“对标……”）；
- 只写简称、只写文号的。
输出：| 原文写法 | 你判断指的是哪份文件（拿不准写“不确定”） | 类型 | 页码或段落 |。
不要遗漏重复出现但写法不同的。不超过 N 字。
```

### 依据兜底：应列未列

```
本项目是 <项目一句话，地点、领域、规划期>。
按 plan-work 的 references/政策与公文检索.md，到国家、省、市、区四级政府和主管部门官网，
查 <领域> 近三年的现行规划、政策、标准，找出这类成果通常要落实的文件。
工具：优先用 python3 -I scripts/govdoc.py（国家级用 central，行标/地标用 std，地方用 search --track <轨道> --region <地区> 或 list 翻栏目，原文核对用 fetch）；<其他本轮试通的命令>。
另核下列文件的现行状态（是否已正式发布、成文与发布日期、有效期/试行期、是否被废止或取代）：<只列状态为在编、征求意见稿或可能过期的文件名>。
输出：| 名称 | 文号 | 发文机关 | 成文/发布日期 | 现行状态与有效期 | 来源等级(T1-T5) | 和本项目的关系（一句话） | 链接 |。
严禁暴力扫站点 ID 或伪造绕过 403/412；找不到的写“未找到”和试过的站点与关键词。不超过 N 字。
```

不给它材料里已经列了哪些依据，免得它只去核清单；要核状态的文件单独列。

### 参考稿写法研究

```
本项目是 <项目一句话>。用户要学 <参考稿清单> 的写法，只学结构和规律，不照抄原句。
逐份研究，每条注页码或章节，原文放引号里，你的判断标【判断】：
1. 纲领式提法：原文、由哪几件事组成、出现在哪几处、自创还是沿用上级；
2. 原则、目标、策略、任务的标题句式，每类 3—5 个原文例子；
3. 政策背景段：引用顺序和格式、引文后有没有插本地的话、篇幅、有没有罗列；各给 2 个例段；
4. 上位提法清单：每份稿用了哪些、怎么写、放在哪一节；
5. 品牌名和地方说法的命名方式和用处；
6. 共同规律、差异，哪些太公文、太口号、不自洽。
输出：按 1—6 分节，表格为主，不超过 N 字。
```

### 上位提法原文

```
本项目是 <项目一句话>。到官网摘下列文件里和 <领域> 相关的原句，照抄，每条给链接和段落位置：<文件清单>。
另查清这些提法最权威的正式出处、近两三年的中央文件里是否还在用：<提法清单>。
工具：<能用的检索命令>。
输出：| 提法或原文句子 | 出处文件 | 位置 | 链接 |；找不到的写“未找到”和试过的关键词。不超过 N 字。
```

这两路可以和“依据兜底”同时派。

### 前提工作包：对账和测算复核

```
这是前提工作：只读，不改项目文件，不出页面、不写正文。按 plan-work 的 references/工作模式.md“前提工作”做。

项目：<项目一句话>。项目目录：<路径>。
背景：<要支撑的推导顺序，如现状特征 → 需求 → 目标 → 项目；上级意见原件路径>。

先读：<核算记录、大纲、测算表及工作表名、数据表路径>。

已定口径，不再讨论：
- <逐条列：关键假设的取值、算式、比较对象>

已知的不确定之处，不用再报：
- <逐条列>

要核的事：
1. 算式和数能否从数据文件复算，单位和口径（面积、套数、用地；出让、开工、入市、竣工）有没有混用。
2. 各来源之间按项目对账：同一项目有没有重复计入或漏计。
3. 本项目的数和上位指标是否同一统计口径（先抄上位的定义原文）。
4. 规则是否套用到全部对象；算式里有哪些隐含假设。
5. <本次特有的问题>

要求：
- 只报会改变已定值方向、或影响超过 <阈值> 的问题；小问题合成一段。
- 发现问题就给出你认为对的算法和你算出的数；拿不到数时给区间和依据，不写“需要核实”了事。
- 不定目标取值，不选情景，不评价方案能不能成立；几种口径都说得通时，并列各口径下的数。
- 每条写位置、原来的算法和数、问题、对已定值的影响（多少、方向）、依据；每条三四个关键数，明细放附表。
- 开头一两句先说已定值受不受影响。判断标【判断】。
```

任务说明里给已定口径和推导顺序，但不给我们对“哪里可能有错”的猜测，免得它顺着去证实。

### 独立核验

```
核下面这些数是否有正式出处、口径是什么：<数据项 + 数值>。
可能的来源：<来源类型>。
每个数给出原文、链接和口径；找不到就写“未找到”和试过的关键词。
```

独立核验只给要核的数，**不给我们的判断**，免得它顺着我们的预期去证实。

## 回收

- **抽查：** 凡是要进结论的数、子 agent 之间说法冲突的数，主会话回原文核。核过的在底稿“核验”列写“已核”。
- **合并：** 统一表头，状态用五类（可用、待核、有误、无出处、缺）。
- **存原件：** 从子 agent 下载的文件里挑出有用的，存进项目的 `原始资料/网上公开资料/`。
- **向用户汇报：** 先说找到了什么、能直接用什么，再说口径冲突和确实找不到的；不要原样转发子 agent 的报告。
