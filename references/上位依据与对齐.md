# 上位依据与对齐

评审拿到成果，先看依据：列得全不全、是不是现行版本，正文的定位、目标、指标、提法和上位文件一不一致。依据清单在开工时就建，写作时逐条对齐。

## 1. 从哪里找

先看**当前阶段成果**怎么列，它是本项目已经认定的依据，下游成果跟着它走：

- 规划文本、编制说明、汇报稿里的“编制依据”“规划依据”章节；
- 背景、形势、规划衔接、上位要求这几章，以及“落实《……》”“依据《……》”“对标”的句子；
- 汇报稿的依据页、政策页（含备注和版面外对象）。

再看任务来源（合同、任务书、同事交代）点名的文件，和同事底稿引用的文件。

用 `scripts/extract_refs.py` 先扫一遍：

```bash
python3 -I scripts/extract_refs.py 规划成果 专题合同要求.docx 同事底稿.docx --out 依据清单_自动提取_YYYYMMDD.xlsx
```

它抓书名号里的名称、文号和标准编号，并找出各材料的“编制依据”章节，打印一张对照表：同一份依据在每份材料里怎么写的。

### 子 agent 兜底

脚本只认格式，会漏。脚本跑完，再派子 agent 各自找一遍，专门防遗漏。两路并行：

- **材料通读：** 一份主要材料一个 agent（阶段成果的文本、编制说明、汇报稿，任务来源）。逐段读全文，找出所有指向上位要求的提法，包括脚本抓不到的：没有书名号的文件名（“中共中央关于制定……的建议”）、会议和讲话（中央城市工作会议、全会精神、总书记重要论述）、笼统提法（“按照国家、省、市有关要求”“对标先进城市”）、只写简称或只写文号的、PPT 备注和版面外对象里的。
- **应列未列：** 一个 agent 到国家、省、市、区四级官网查本领域近三年的现行规划和政策，找出材料一份都没提、但这类成果通常要落实的文件；顺带查清单里“在编”“征求意见稿”的文件是否已经正式发布，以及已列文件是否被废止或取代。

规矩：

- **不给脚本的结果。** 只给文件路径和项目背景，让它独立找，主会话再拿两边的结果对比。给了清单，它就只会去核清单。
- 每条注原文和页码（应列未列的注链接和发布日期），说不清出处的不收。
- 主会话合并：脚本漏掉的补进依据清单，“提法”类记进依据要点；应列未列的单独列，和用户讨论要不要补。
- brief 模板见 `子agent分派.md`“依据兜底”。

## 2. 整理成依据清单

脚本结果并进工作底稿的“依据清单”页，人工整理：

| 名称 | 文号 | 类别 | 层级 | 列入依据章节 | 现行状态 | 本项目怎么用 | 核对 |
|---|---|---|---|---|---|---|---|

- **类别：** 法律法规、政策文件、相关规划、标准规范。
- **层级：** 国家、省、市、区。
- **列入依据章节：** 写哪份阶段成果列了它、原文怎么写的（含“在编”“征求意见稿”这类状态）。
- **现行状态：** 现行、已废止、被取代（写被什么取代）、征求意见稿、在编；写明查证的链接和日期。
- **本项目怎么用：** 对应哪些合同条目或章节，要落实的是定位、指标还是任务。
- 同名不同写法、简称（如《住房规划》）并成一条，简称写在名称后面。
- 脚本误抓的（地图审图号、统计年鉴、本项目自己的成果名）删掉或标“非依据”。

整理时要看出来的几件事：

1. **各阶段成果列的依据不一样**：条数不同、版本状态不同（一份写“在编”，另一份写“征求意见稿”），列出来问用户以哪份为准。
2. **底稿引用了、阶段成果没列的文件**：可能是新出的政策，也可能是底稿自己加的，列出来问用不用。
3. **过期和被取代**：逐条到发文机关官网查原文。被取代的改用新文件并告诉用户；“在编”的上位规划，查有没有已发布的征求意见稿或正式稿。
4. **任务来源点名但哪里都没有的文件**：要补。

依据原件下载存进 `原始资料/网上公开资料/`，和数据原件放在一起。

## 3. 摘依据要点

主要的上位规划和政策（通常五到十份），每份摘出和本项目相关的内容，放进底稿“依据要点”页：

| 依据 | 条款或页码 | 原文 | 类型 | 对应本项目条目 |
|---|---|---|---|---|

- 类型：定位、目标、指标、任务、空间安排、政策要求。
- 原文照抄，不改写，不概括。
- 几十页的规划纲要、专项规划派子 agent 通读抽取，一份文件一个（模板见 `子agent分派.md`）。
- 上位文件之间的要求对不上（比如市级规划和区纲要的指标不同），列出来问用户。

## 4. 写作时对齐

- **依据列表跟阶段成果一致。** 条目、名称、文号、状态写法照阶段成果；要增删的先问。没有现成顺序时按法律法规、政策文件、相关规划、标准规范排，同类按国家、省、市、区。
- **名称写全称。** 第一次出现写全称加文号，后面用阶段成果已有的简称，不自己起简称。
- **提法照上位原文。** 定位、目标、口号、专有说法（如“好房子”的“五好”）照原文写，不改字，不另造新提法。
- **指标不冲突。** 目标值、时限、规模不突破、不矛盾上位和阶段成果；分解到本项目的数，写明是怎么分解的。
- **名字一致。** 片区、项目、街道、园区的名称和上位文件、阶段成果一致。
- **策略有来由。** 每条策略能追到依据要点表的一行，或本地的事实和问题。两头都追不到的，是我们自己提的，讨论时标出来。
- **不罗列政策。** 背景只写和本项目直接相关的依据；本地怎么落写在后文，不在每条后面接一句（见 `写作语言.md`“不旁征博引”）。
- **引用未正式发布的文件**，照阶段成果的写法注明状态；正式发布后全文统一更新。只标公开的状态（征求意见稿、草案、在编），不标送审稿、报审稿、讨论稿这类内部过程版本，读者不需要知道我们手里拿的是哪一稿。

## 5. 修订痕迹

阶段成果的 Word 常带修订痕迹。`extract_text.py` 输出的是接受修订后的正文，删掉的文字附在末尾。删掉的句子常是规划组有意改掉的提法和口径（比如把“以需定建”改成“以需定供”、删掉“原则不再新建”），下游不要把它们写回去；和上位文件不一致的，告诉用户。

## 6. 提法库

政策提法和口号单独建一页“提法库”，写作时查。

1. `extract_refs.py ... --phrases` 统计各材料引号里的提法，看哪些多份材料都用、写法是否一致。
2. 派子 agent（模板见 `子agent分派.md`）：一路读参考稿（同级、上级的同类成果），研究纲领提法、标题句式、政策背景段的写法；一路到官网摘上位文件的原句，核提法的最权威出处和是否还在用。
3. 整理成表：

| 提法 | 层次 | 最权威出处（原文） | 规划成果里的写法和位置 | 专题怎么用 | 用在哪些专题 |
|---|---|---|---|---|---|

层次分五类：上位定式、本市通行、本区已定、有分歧、不用。写法规则见 `写作语言.md`“政策和提法”。

## 7. 交稿前核一遍

对成稿再跑一次 `extract_refs.py --phrases`，和依据清单、提法库对照：

- 正文里每个书名号都在依据清单里，状态是现行（或已注明状态）；
- 同一文件、同一提法全文只有一种写法；
- 没有提法库里标“不用”的提法；
- 依据章节和阶段成果一致，差异是用户同意过的。
