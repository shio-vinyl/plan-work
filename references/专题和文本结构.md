# 专题和文本结构

规划文本、配套专题怎么搭结构、每节写什么、内容从哪来。句子怎么写见 `写作语言.md`，上位依据怎么梳理见 `上位依据与对齐.md`。例子来自住房规划配套专题，换成别的规划类型道理相同。

## 1. 定位和分工

- **弄清这份文本在成果体系里的位置。** 配套专题是对已定成果的解释和深化，不另立指标。多个专题时，先分清总括专题（概括成果、统领其他专题）和分领域专题（各自展开）。
- **规划文本重广度，不重深度。** 按“几个方面”铺开，以结论和定性判断为主，推导过程和测算细节不进正文。
- **先列分工表。** 每类内容只归一个专题写透，其他专题点到为止；同一文件的同一条款只在一个专题引用。专题之间的区分度来自分工，不来自措辞。分工只在总括专题开头交代一句，正文不写“详见专题×”“见专题×”。
- **母本用成果，不用底稿。** 审议稿、编制说明、汇报稿是母本，汇报稿的页序往往就是最好的故事线；同事底稿只借外壳。
- **合同条目就是方面清单。** 合同、任务书的原话常常已经列好了方面（例：“规范化、品质化、高质量发展”“提升住房品质、优化居住体验、提高管理效率”），直接用作主轴或策略分组，评审逐条对照时一眼能找到。

## 2. 外壳不动，内部一条线

底稿或委托方要求的固定外壳（例：研究背景、研究基础与前提、研究技术路线、研究原则、研究思路、研究结论）可以保留，内部按一条线串：技术路线定步骤，原则各管一步，研究思路是各步的结果，结论逐条收回。

- **主轴：一组方面，前后各走一遍。** 每个专题选一组方面作主轴，在评估和目标里各走一遍，策略的分组和它对应。例：总括专题用人、房、地、钱 ×（上一期实施情况、本期目标）；房地产用商品住房的开发环节（已竣工待售、在建、已供地未动工、新出让）；物业用按产权分的小区类型；科技用合同点名的几类技术 × 几种作用；住房与产业用规模、结构、空间、时序。
- **同层同类，三组三项。** 同一层的标题必须是同一类东西，目标、策略、保障不平铺；实施保障、制度改革拆进它服务的那条策略，在结论里集中列一遍，方便对照合同。策略三组、每组三项最稳，每组开头一句下定义，说清这组是什么、管什么。
- **检验：** 每条策略能往回追到一个问题和一条原则；追不上的，就是散了。
- **结构卡住时，先跳出外壳：** 想清楚“如果这是一份汇报，应该怎么讲”，故事线定了再装进外壳。

## 3. 每节只做一类事

文件说了什么、本地现在怎么样、本地要怎么做，是三类东西，各有各的节。一节里混进别的类，多半是插进去的（见 `写作语言.md`“不旁征博引”）。

| 节 | 写什么 | 不写什么 |
|---|---|---|
| 背景 | 开头一句说明本文对应成果的哪些指标和任务；上位要求按国家（和省）、市、本地分层，每层一句总述，再按文件分条：文件名开头，引原文 | 本地的现状、做法和评价；按主题归纳；一句话列一串文件名 |
| 基础 | 现状和上一期的成效，都是事实 | 推论、问题、策略 |
| 前提（形势） | 照成果的说法写 | 后补的本地细节和推论 |
| 技术路线 | 本项目实际的步骤，通常评估、测算、施策三步；没有量可测的领域，中间一步改为研判 | 方法论；和其他专题一字不差的套话 |
| 原则 | 条数和步骤对应，每条管一步；原则原文加成果里的解释原文 | 后接“本地按……” |
| 研究思路 | 三步走完的结果：评估（含问题）、目标、策略。问题紧挨策略写在这里 | 复述技术路线 |
| 结论 | 逐条收回研究思路，最后一条写指标和制度；指标带名字 | 新内容 |

背景的两个细节：

- **本地层可以直接写要求。** 本级规划对本地的要求本来就在讲本地，可以接一句“本地……”写明，主语写出来；上位文件点名本地的原句照引。
- **防乱引用。** 引用和后文接不上的删掉；原文里没有本地相关条款的文件不引（例：只在新闻里提到的工程、没有住房条款的总体部署）。引用逐句对照原件核对，核不到的说法改写或删除。

## 4. 内容从哪来

- **尽可能用已有的，缺的才自己提。** 写策略前先在已定成果里找原话、项目名单和做法；成果没有的，再找上位文件和官方资料；都没有的地方才由我们提。合同要求的制度改革建议、按住房类型或主体分配的做法，往往只能我们提，这不是问题。
- **自提的不能和成果冲突，也不能把成果写硬。** 举例语气不写成定数（“如控制在10%以内”）；下限不写成上限（“不少于3公顷”）；需求量不写成“不超过”（“约40万平方米”）；“择机开展前期谋划”“划定试点范围”不写成“开展试点”“试点建成”；成果的提法不替换（成果写的是“部门监管、街道统筹、业主自治”，就不换成别的口号）。
- **类型和人群的对应照政策定义写。** 公租房、保租房面向谁，照办法的定义条款写；自己推出的对应（户籍对应公租房、非户籍对应保租房）没有充分理由就不写，要写就放进研究思路并说明理由。
- **数据少而清楚。** 只留直接决定定性判断的数。留下的数说清含义和口径：方括号是不是累计值，指标由哪几部分组成，比例的分子分母，容易混的术语第一次出现就下定义（例：宽口径“保障房”和窄口径“保障性住房”；成果测算中“片区住房”不含产业宿舍）。同一个量只用一个口径（例：人口只用规划编制成果口径，不再并列统计公报）。
- **来源分档。** 已定成果为主，外部资料能不用就不用；成果材料明显不够时，补用官方网站公开、来源不偏的资料（公告公示、统计公报和年鉴、普查年鉴、政策原文）。平台数据、招聘网站、新闻转载不用；按假设自建的测算模型不进正文，评审对外部数据和自建模型的可靠性很敏感。合同要求“模型”“形势预测”时，沿用成果自己的测算方法和判断。
- **来源只露正式名义。** 正文引规划原文写规划的正式名称，引测算和数据写“规划编制成果”，不点名审议稿、编制说明、某日汇报稿；版本状态只标公开的（征求意见稿、草案、在编），不标送审稿、讨论稿。
- **检验：** 定稿前按举措逐条溯源，分成成果原有、其他已有材料、自己提出三类，看比例，再逐条核自提的有没有和原文冲突。成果材料少的领域自提比例高是正常的，要看的是能用已有的地方有没有漏用。

## 5. 过程

1. 先出结构草案（标题加每节放什么、用什么材料），和用户讨论定了再写稿。
2. 多个专题时，先拿最难或最总括的一个做样板，把规矩磨定，再推广到其他专题。
3. 每定一条规矩就写进项目的框架文件（整体思路、各专题框架、分工、写法），后面的专题和会话照着执行。
4. 改稿另存新文件，旧稿定稿后移进 `_归档/`。
5. 定稿前按 `写作语言.md` 末尾的自查清单过一遍。
