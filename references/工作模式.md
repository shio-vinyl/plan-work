# 工作模式：前提工作和方案工作

规划项目里的活分两类，想法不同。看的是这件活属于哪一类，不看谁来做：主会话、子 agent、另一个协作的 agent，做前提工作时都按前提工作的想法，做方案工作时都按方案工作的想法。

一件活两类都有的，拆开做：前提工作先交，方案工作在它的成果上做。

## 怎么分

| | 前提工作 | 方案工作 |
|---|---|---|
| 做什么 | 资料整理、数据提取、口径核对、跨来源对账、测算复核、情景计算 | 定目标和指标取值、选情景、取舍、定结构、写文本和汇报页 |
| 依据什么 | 原文和数据 | 前提工作的成果、上位要求、用户定下的口径 |
| 交什么 | 数据表、对账表、口径卡、情景表，加一份影响说明 | 方案、文本、页面 |
| 结论的样子 | 在已定口径下这个数是多少，受哪些因素影响、影响多大 | 采用哪个，为什么，代价是什么 |

## 前提工作

### 怎么想

1. **先查口径定义，再比数。** 上位指标常在附录、名词解释或指标说明里写了统计口径：按开工、供应（批准预售和现售）、入市还是竣工统计，含不含安置房、公寓、宿舍。比数之前，把定义原文和位置抄进口径卡（格式见下）。例：上位的“新增建设住房”按正式开工统计，本地按人口推出的住房缺口就不能直接和它比。
2. **跨来源按项目对账。** 现状底数、在建续建、在售库存、供地计划常出自不同的表（建筑普查、供地台账、房地产信息平台），同一个项目可能同时出现在几张表里。用宗地号、项目名、位置逐个对，出对账表，每个项目只计一次，写明归在哪一项。不用比例代推重叠的部分，比例推出来的数看着合理，可能差几倍。例：一宗前年出让的住宅，普查已按建筑面积计入现状，供地台账又按“出让后三年入市”计入续建，同一批面积减了两次。
3. **时序字段分列。** 每个项目的出让、开工、预售、竣工年各占一列，注明是记载的还是推的，推的写规则。这样按哪种口径都能直接加总，不用每次重推。
4. **规则全量套用。** 筛选或时序规则定了，就对全部对象套用；只取一部分时，写明理由和取舍前后的数。结果凑巧和目标值、上位值对上，要明说，不当作印证。
5. **隐含假设写出来。** 算式里默认的前提（期末库存清零、全部在期内入市、实施率 100%）列出来，并给出换成合理取值后的结果。
6. **核对类别。** 项目名、用地性质、批文显示是保障房、安置房、配套用房、宿舍的，不跟着来源表归进商品住房；改了类的列出来。

数据纪律照 SKILL.md：每个数有出处，状态分五类，推算单独标。

### 边界

- **已定口径冻结。** 任务说明列出的已定口径和推导框架不重新讨论，也不另起一套框架。发现会动摇已定值的问题，写成“对已定值的影响”：多少、哪个方向、依据是什么。改不改，由方案工作定。
- **不下方案结论。** 不定目标取值，不选情景，不评价方案“能不能成立”“能不能证明”。几种口径都说得通时，并列各口径下的数，写清差在哪里。
- **只列真缺口。** 只缺原文的、确认性的不列。能用已有资料算的先算，给出区间和依据，不写“需要核实”“数据不足”了事。
- **不改结构、不写正文和页面文字**，不改项目的成果文件。

### 交什么

- **文件：** 对账表、口径卡、情景表等，命名照 `文件组织.md` 的数据层；写到任务说明指定的位置。
- **说明，按这个顺序：**
  1. 已定值受不受影响：一两句，给数和方向。
  2. 发现，按影响从大到小排。每条写：位置（文件、页、单元格）、原来的算法和数、问题、影响量和方向、依据（原文或数据行）。每条只放三四个关键数，明细放进文件。
  3. 小问题合成一段。
- **事实和判断分开**，判断标【判断】。

### 口径卡

| 指标 | 上位文件 | 定义原文 | 统计口径（开工、供应、入市、竣工） | 含不含（安置房、公寓、宿舍） | 位置 |
|---|---|---|---|---|---|

### 对账表

| 项目（宗地号、名称） | 来源一的记法 | 来源二的记法 | 来源三的记法 | 归类 | 计入哪一项 | 依据 |
|---|---|---|---|---|---|---|

## 方案工作

1. **目标是安排出来的。** 规划目标用上位的指标名和统计口径，由规划期内安排哪些项目、按什么时序来定。需求测算、销售推算是校核，用来说明目标合不合理、有没有余量，不要求它们“证明”目标值。上位分摊值作底线。
2. **推导链要接上。** 上级或用户要的推导顺序（比如现状特征、需求、目标、项目、策略）是方案的骨架。某一环在数据上接不上，就找出断在哪，换口径或补一环把它接上，并写明代价；不因为一环不成立就放弃整条链。
3. **取舍写清代价。** 选一个情景，写明放弃了什么，什么条件变了要改。
4. **关键假设先讨论。** 人口这类关键假设明显高于上位预期时，先拿出来讨论，再写进目标。
5. **并列的数先对齐口径。** 同页或前后页并列、名字又相近的数（如新增住房、新建住房），写清各自的口径和换算关系。

方案工作用前提工作的成果。要进结论的数，回原文核过再用（见 `子agent分派.md`“回收”）。

## 派活时

- 任务说明第一句写明是前提工作还是方案工作。
- 前提工作的任务说明带两段：“已定口径，不再讨论”和“已知的不确定之处，不用再报”。模板见 `子agent分派.md`“前提工作包”。
