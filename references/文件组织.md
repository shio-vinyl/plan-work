# 文件组织

第一目标是人能看懂、能审核，不追求最严谨。

## 目录

```
<项目>/
  工作记录.md                  接手从这里开始
  <主要成果和工作底稿>          根目录只放现行版本
  规划成果/ 或 研究稿/          甲方、同事的现成成果
  原始资料/                    收到的东西，原样不动
    网上公开资料/              自己下载的年鉴、公报、附件
  数据表/                      提取出的表，一表一个 xlsx，附 00_数据表目录.xlsx
  脚本/                        生成表格、出图的脚本，附 README
  _归档/ 或 历史/              被取代的旧版和重复件
```

- 层级尽量少，整齐但很深的目录对人反而不方便。
- 不动不动新增文件。能并进已有底稿的，加一页，不另建一本。
- 原件只读；被取代的移进 `_归档/`，不删除。
- 过程文件到期就压：渲染图在一轮交付 7 天后删（随时可重渲）；带日期的过程目录（如 `改稿_20261104/`）过了 14 天，里面的 pptx、图片、PDF 打成一个压缩包，文字文件留在原地；历史目录每条汇报线留最新两版，更早的超过 14 天也打包。用 `scripts/archive_process.py`：先 `plan` 把清单给用户看，用户同意后 `apply`；要用某个旧文件时 `extract --match` 单取一个，解回原位置。资料目录、根目录现行稿不碰。

## 命名

- 文件名写清内容和日期：`商品住房成交情况周报_20260315.xlsx`。
- 交出去过的文件再改时另存新版本（v2、v3），不覆盖：对方可能正开着，WPS 开着时文件被覆盖，图片会显示成白框。

## 数据层：表格先提成数据表

材料里的表格（PPT、PDF、Word、图片、Excel 的各个工作表）和 GIS 图层的属性表，都先提成数据表，再做分析。数据表直观，能逐行核对，也方便别人接手。

- **一张表一个文件**：单工作表的 xlsx，放在 `数据表/`。
- **文件名：名称_来源_提取日期.xlsx。** 名称写表的内容；来源写来源文件的简称加位置（页码、表号；GIS 写库名，图层名就是名称）；日期是提取那天。例：
  - `在建项目清单_汇报稿p12_20260315.xlsx`
  - `期末住房库存_编制说明表1_20260315.xlsx`
  - `公共服务设施点位_设施普查库_20260315.xlsx`（GIS 图层）
- **登记目录** `数据表/00_数据表目录.xlsx`，每张表一行：文件名、名称、来源文件、位置、提取日期、提取方式、行数、列数、需要注意、核对。
- **提取方式**分六种：PPT表格、Word表格、PDF自动识别、Excel分表、GIS属性表、图片转录。PDF 自动识别和图片转录的表，要对照原文核一遍合计和关键数，核过的在“核对”列写“已核”。
- **只提取，不改数。** 多行表头、合并单元格可以整理成一行表头；数值照原文。发现原表有错，在计算层更正并写明理由，数据表不动。
- 编码列（编码、代码、编号、宗地号、地块号）存成文本。
- **资料更新时重新提取**，文件名带新日期；旧表移进 `历史/`，目录里写明被哪张取代。

用 `scripts/extract_tables.py`：

1. 先加 `--list`，看会提出哪些表、自动取的名称对不对。
2. 名称不合适的用 `--name 来源位置=名称` 改（如 `--name 汇报稿p12=在建项目清单`）；来源文件名太长的用 `--alias 原文件名=简称`。
3. 去掉 `--list` 正式提取，输出到项目的 `数据表/`，目录自动登记；已登记的同名文件不会被覆盖。
4. 图片里的表格，脚本只输出 OCR 文字。表格由 agent 看图转录成 xlsx，用 OCR 文字核数，自己登记进目录，提取方式写“图片转录”。

**分析只从数据表取数。** 测算表、成果表、文本里的每个数，都要能追到某张数据表的某一行，再追到原文件的某一页。不要从 PPT、PDF 里直接抄数进测算表。

## 空间分析和计算层

- **空间关系**（叠加、近邻、切分）先在 GIS 里做成分析成果图层，再把属性表提成数据表；另记一份 GIS 操作记录，写清对哪些图层做了什么。
- **计算层：** 一本多工作表的测算 Excel。参数集中放一页；一行是一个人能理解的对象（一个项目、一块地）；人工判断标色并写理由；留核对区，差额应为 0。
- 测算表由脚本从数据表重新生成；只改参数时直接改参数页。

## WPS 兼容

甲方和同事多用 WPS，生成的 Excel 只用 WPS 支持的函数：不用 Power Query、XLOOKUP、MAXIFS、动态数组。`.et` 是 WPS 表格格式，读之前用 `soffice --headless --convert-to xlsx` 转换。

## 工作底稿

研究类项目的工作底稿通常是一本 Excel：

| 页 | 内容 |
|---|---|
| 合同条目分类 | 见开工盘点第 4 节 |
| 依据清单 | 上位规划、政策、标准：名称、文号、列入哪份成果、现行状态、本项目怎么用 |
| 依据要点 | 上位文件和本项目相关的原文，注条款页码 |
| 提法库 | 提法的层次、最权威出处、规划成果里的写法、专题怎么用 |
| 数据清单 | 要用的数：状态、底稿写法、可靠来源的数、来源、下一步 |
| 公开数据 | 查到的数，每条带链接 |

## 工作记录模板

```markdown
# <项目名> · 工作记录

> 负责：……｜最后更新 YYYY-MM-DD｜路径相对项目根目录
> 新会话从这里接手。

## 一、文件放在哪
| 位置 | 内容 |

## 二、怎么更新
（资料到了改哪里、跑什么脚本）

## 三、现在的状态
（每项任务做到哪、主要数字）

## 四、已定口径
（日期 + 口径 + 理由）

## 五、资料现状
（拿不到的、暂时没有的、影响不大先不管的）

## 六、更新记录
| 日期 | 内容 |
```

## Word 成果

- 版面、分页、页码用 Microsoft Word 导出 PDF 核对；LibreOffice 渲染和 Word 差距很大，不能用来判断分页。
- Word 把文件打开成未命名的“文档1”，说明它悄悄修复了文件，要查原因。
- 填模板时，关键信息有选择地标红，待补项黄底写【待填】。
